# 小白概念教程：工作流是什么、设置页每一区块在管什么

> 写给完全不懂技术的你。你正在用的这套 AI 环境（live，即正式在跑的那套）刚升到 v0.2.1（版本号，可以理解为"第几次改良款"），Grok workflow 插件已经激活、工作流已开启，但四个角色链还空着，暂时全用默认模型——这句话是什么意思，读完第三节你就懂了。
>
> 本篇只讲"是什么、为什么"：不给推荐配置值、不列字段字典、不讲安装升级。哪里拿不准，以设置页自带的提示为准。

## 一、这东西是干嘛的（2 分钟版）

装了这个插件后，你每发一条消息，AI 不再"随口直接回答"，而是必须走一条固定流水线：把你的问题拆成小任务 → 干活 → 逐条核对 → 交出一份带证据的报告。这份报告才是你看到的回答。

用生活话打比方：以前像厨师听你点单随口应一句"马上好"；现在是后厨接单、配菜、炒菜、质检，端上来的菜附一张小票——哪道好了、哪道没好、还有什么不确定，全写在小票上。"我说做完了"这句话本身不再算数，证据才算数。

小任务的"验收标准"（每条要求怎样才算做到的检查清单）在拆任务时就定好，核对时一条条对着要证据，所以回答里说"完成"的，都是真核对过的。

## 二、核心概念白话讲解

### 1. 工作流（workflow）与"每条消息强制走工作流"

工作流就是上面那条"拆任务 → 干活 → 核对 → 汇报"的流水线，四个环节固定不变。

"强制"的意思是：插件在门口设了一道**门禁**（也叫闸门）。你发出的每一条消息都会被门禁接走、跑完整条流水线；**主模型**（平时直接跟你对话的那个模型）不能绕过门禁自己抢答。这是刻意设计：不把"我说做完了"当成任务完成的证据。

**与普通直答的区别**：普通直答是一个模型一口气想到哪写到哪，没人核对；工作流回答是拆解、执行、逐条验证之后的结果——"完成"只给通过验证的任务，没做到的、拿不准的也如实列出来，流程本身失败时它会明确说失败，绝不会装成一份成功答案。

### 2. in-turn 交付（在同一轮对话里交货）

in-turn 直译"轮次内"。意思是：报告在你这一轮提问还没结束时就交到主模型手里，由它把报告转达成你看到的回复——你问一句、等一会儿，答案就在这一轮里回来。像堂食：点完单坐着等，菜在同一次就餐里上桌。

另一种做法是"先关门、稍后再送"（设置页里叫 relay、append，留给长期开着的界面用）。小白不用管它，认准默认的 in-turn 就行。

### 3. `<<<GROK-WORKFLOW-REPORT>>>` 报告

流水线跑完会产出一份**结构化**报告（结构化 = 格式固定、人和机器都能读）。报告被夹在一对标记里：开头是 `<<<GROK-WORKFLOW-REPORT>>>`，结尾是 `<<<END-GROK-WORKFLOW-REPORT>>>`。主模型的职责是把标记里的内容原样转达，不添一个字。

报告第一行是状态，只有三种：

- **COMPLETED** —— 全部任务通过验证；
- **PARTIAL** —— 一部分做到，还有没完成或拿不准的；
- **FAILED** —— 没跑出可用结果。

后面依次是：拆了哪些任务、每条验收标准的证据、没完成的事项、不确定项。和普通直答最大的区别就在这：它是核对过的账本，不是自由发挥。

### 4. 角色链：四个角色各干什么、按角色选模型

流水线上有四个固定岗位（**角色**）：

- **规划**（planner）：把你的问题拆成带验收标准的小任务；
- **执行**（worker）：领任务干活，可以几个人同时干；
- **验证**（verifier）：换一个全新的检查员，对照验收标准逐条要证据；
- **综合**（synthesizer）：把大家的结果汇总成最终叙述。

**生活类比 ①（角色链）**：像家里装修——画图纸请设计师，施工请工程队，验收请第三方监理，写总结请文案。四个环节各干各的，可以分别请不同的人。

"按角色选模型"就是给每个岗位指定用哪个模型干活。设置页里每个角色配一条**角色链**，链上最多放 3 条**路由**——路由就是"用哪家的哪个模型"的组合。这里有三个名词要解释：

- **provider**（模型服务商／接入渠道）：就是"用哪家"，某个模型服务的代号；
- **模型标识**（model）：就是模型的名字编号，"用哪个"，类似 xxx-large 这样的名字；
- **spawn**：你这套工具（DSH，即 DeepSeek Harness 桌面 AI 环境）自带的一种 provider，作用是在本地"生出"干活用的**子代理**（小号分身），不算外部服务商。

角色链留空 = 该角色使用**会话默认模型**，也就是平时跟你对话的那个模型。

### 5. 备用链：主模型不可用时如何接力

角色链上的 1、2、3 号路由不只是排队，还是替补席，这就是**备用链**。

**生活类比 ②（备用链）**：请师傅上门修水管——先请 1 号师傅；他没空、联系不上（服务繁忙被暂时拒绝叫"限流"，还有服务出错、连接失败、超时、模型不可用这些"路不通"的故障），就换 2 号师傅，再不行换 3 号。但有一种情况不换人：师傅来了、活却干得不合格（任务没做好、验证没通过）——换人没用，因为换个人看到的是同样的材料，所以让同一个师傅返工重试。**只有"路不通"才推进备用链，"活不好"原地重试**。三位师傅都试过还不行，任务就如实报失败，绝不悄悄算成功。

哪些故障算"路不通"默认已经配好，小白不用动。

**顺带一提（并发上限）**：设置页里每条路由还有第三个小框"并发上限"（1–64，留空=不限）。它是"这条路同时最多几个人走"——打满时新来的会自动让到下一条路由，不算失败、不换备用链、不消耗重试。只有全部路由都打满才排队等一会儿。平时不用动，想让某条慢路少接活时再填。

### 6. 现状速读：强制工作流 + 四条空链 = 全用默认模型

把开头那句话翻译成人话：现在门禁开着（自 v0.2.0 起每条消息强制走工作流），但四个角色链都是空的。空链的含义就是"使用会话默认模型"，所以规划、执行、验证、综合四个岗位**目前全由同一个默认模型兼任**。一切照常能用；等你想给不同岗位挑不同模型、或想配替补时，再去动设置页的角色链区块。

### 本篇行话小抄

| 行话 | 白话 |
| --- | --- |
| provider | 模型服务商／接入渠道的代号，"用哪家" |
| spawn | DSH 自带的 provider，在本地生出干活的子代理（小号） |
| 模型标识（model） | 模型的名字编号，"用哪个" |
| 路由（route） | provider + model 的组合："用哪家的哪个模型" |
| bundle | 打包好的插件部件；设置页能出现在网页里，靠的是插件自带的浏览器 bundle |
| 主模型 | 平时直接跟你对话的那个模型 |
| 子代理 | 被派去干具体活的小号分身 |
| 验收标准 | 每条要求"怎样才算做到"的检查清单 |

## 三、设置页布局导览（从上到下）

设置页在：网页界面 → 设置 → 插件 → **Grok workflow** 卡片。整个页面约 21 项：17 项可编辑 + 4 项只读。改动保存后对下一条消息生效。

| 从上到下 | 管什么（对应概念） | 小白该不该动 |
| --- | --- | --- |
| ① 页头说明 | 一句话导览："每条消息都走 计划 → 执行 → 验证 → 综合"（对应**工作流**） | 可不动 |
| ② 入口与门禁 | 门禁管到多大范围、报告怎么送回你手里（对应**强制入口**与 **in-turn 交付**） | 别动（默认就是对的，改它等于动门禁本身） |
| ③ 上下文与并发 | 一次流水线最多拆几个任务、几件活同时干、最多等多久、带上文带多少——工作流的"体力条" | 可不动 |
| ④ 综合、切换与记录 | 最终答案怎么成文（对应**综合**角色）、哪些故障算"路不通"能推进备用链、要不要留下运行记录 | 可不动 |
| ⑤ 按角色模型链 | 四条链：规划／执行／验证／综合，每条最多 3 条路由（provider 可空、模型标识必填），留空即用默认模型（对应**角色链**＋**备用链**） | **小白必动**——唯一真正要动的区块：想按角色选模型、想配替补就在这里；填错会被拦下并告诉你原因 |
| ⑥ 结构性字段（只读） | 工具名、强制门禁开关等 4 项——插件与门禁的"承重墙"，页面只展示不让改 | 别动（本来也改不了；要改得动安装层配置并重启，超出小白范围） |
| ⑦ 底部保存栏 | 保存／放弃修改，旁边有修订号 | **小白必动**——只要改了上面任何一项，就得按"保存"才生效 |

一句话总结：**现在只动 ⑤，改完按 ⑦；②⑥ 别碰，③④ 保持原样。**

## 四、看完你应该能回答的 5 个问题

**1. 为什么我的消息不再被"直接回答"了？**
答：强制门禁把每条用户消息都接去走工作流（拆任务 → 执行 → 逐条验证 → 交报告），主模型不能绕过门禁抢答。你看到的回答是核对过的结果，不是随口直答。

**2. `<<<GROK-WORKFLOW-REPORT>>>` 是什么？**
答：工作流产出的结构化报告的开头标记（结尾是 `<<<END-GROK-WORKFLOW-REPORT>>>`）。标记内的内容已经过校验，主模型原样转达；报告第一行是状态 COMPLETED／PARTIAL／FAILED，后面是任务、证据、失败项与不确定项。

**3. 四个角色各干什么？角色链为空意味着什么？**
答：规划拆任务、执行干活、验证逐条要证据、综合写总述。链为空 = 该角色使用会话默认模型，所以现在四个岗位全由同一个默认模型兼任——这就是"全用默认模型"的现状。

**4. 备用链什么时候换"人"？什么时候不换？**
答：只有"路不通"（限流、服务出错、连接失败、超时、模型不可用等）才按 1 → 2 → 3 的顺序推进备用链；"活干得不好"（任务或验证不合格）不换模型，原地重试。都试完仍不行，就如实报失败。

**5. 设置页哪块现在就该动、哪块别碰？**
答：现在只需要动"按角色模型链"（想按角色选模型或配备用链时）；"入口与门禁"和"只读结构性字段"别动；"上下文与并发""综合、切换与记录"可不动。改完记得按"保存"，下一条消息生效。
