What was deliberately NOT done
  * No second model was tried and no "use a stronger verifier" experiment was run: the data showed
    the failures were not model-caused, so the honest deliverable is the fix plus the statement that
    a stricter/looser verifier is a `roles.verifier` choice. Running a stronger verifier would have
    produced a green sample without fixing the defect users actually hit.
  * The post-fix live runs never exercised the `verifier note:` path (no issues at all in those
    three runs), so no live run is presented as proof of that path; README §4 states this.
  * Docs-only items were not taken as licence to touch code: R3 (CHANGELOG wording), R4 (t46
    correction notes), R5 (token redaction), R6 (20-bundle re-boot), R7 (STATE) are text/evidence
    changes; only R2 needed source changes, and those are confined to src/script.ts + one test file.
