天空看起来是蓝色的，主要是瑞利散射造成的。

太阳光看起来是白色，其实包含各种颜色的光。进入大气层后，光子会与空气分子（氮气、氧气等）发生散射。
散射强度与波长的四次方成反比（∝ 1/λ⁴）。红光波长长（约 700 nm），蓝光波长短（约 450 nm），所以蓝光被散射的强度大约是红光的 5～6 倍。
于是蓝光被空气分子向四面八方反复散射，布满整个天空，我们从任意方向抬头都能看到蓝光进入眼睛，天空就是蓝色的。

几个常见追问：

为什么不是紫的？ 紫光散射更强，但太阳光中紫光成分较少，而且人眼对紫光不敏感、大气对紫外也有吸收，综合起来我们看到的是蓝。
为什么日落是红的？ 阳光斜穿更厚的大气，蓝光在半路就被散射掉了，剩下的直射光以红橙为主。
为什么云是白的？ 云滴尺寸远大于可见光波长，发生的是米氏散射，各波长散射效率相近，所以呈白色。
太空为什么黑？ 没有大气分子可以散射光。

幂等（Idempotency）的意思是：同一个操作执行一次和执行多次，最终结果（对系统状态的影响）是相同的。

通俗地说，就是“重复执行不产生额外副作用”。

关键点
关注的是“最终状态”，不是“执行过程”：执行次数可以是 1 次，也可以是 N 次，但对系统状态的影响结果必须相同。
并非所有重复都无关紧要：幂等操作可以安全重试，这使它成为分布式系统和接口设计中的重要概念。
常见例子
操作	是否幂等	说明
x = 5	✅ 幂等	执行多次后，x 仍然是 5
x = x + 1	❌ 非幂等	每执行一次，x 都会加 1
查询接口 GET	✅ 幂等	查询多次不会改变数据
删除 DELETE /user/1	✅ 幂等	无论删除几次，结果都是“该用户不存在”
插入 POST /order	❌ 非幂等	每调用一次，就会生成一个新订单
幂等性的实际用途
安全重试：网络超时导致结果未知时，可以直接重试，不会重复扣款或重复下单。
保证消息的“至多一次”效果：消息队列可能重复投递，消费端若做到幂等，就能避免重复处理。
HTTP 方法语义（RFC 7231）：GET、PUT、DELETE 被定义为幂等，POST 通常不是。
实现手段：唯一业务键（如订单号）、幂等令牌（idempotency key）、数据库唯一约束、去重表、乐观锁或版本号。
一句话总结

幂等就是“重复执行，结果不变”；它并非“锁住不许再执行”，重点在于多次执行不会改变最终结果，因此可以安全重试。

Idempotency is the property that performing an operation multiple times produces the same result as performing it once.

In math/computing: f(f(x)) = f(x). Example: abs(abs(-5)) = 5, abs(-5) = 5. Setting a value is idempotent ("set status = active"); incrementing is not ("x = x + 1").
In HTTP/REST: GET, PUT, and DELETE are idempotent by spec — calling them repeatedly has the same effect on the server. POST is generally not.
In APIs/distributed systems: an idempotency key lets a client safely retry a request (e.g., a payment) after a timeout without risking a duplicate charge — the server recognizes the repeated key and returns the original result.

The practical value: safe retries and crash recovery — you can repeat an operation without needing to know whether the first attempt succeeded.
