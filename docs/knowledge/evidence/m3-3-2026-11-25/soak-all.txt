--- migration finding: an old patch must drop the removed keys ---------------

The live profile's own plugin config carried `mode: triage`. The first boot of
the clone refused to activate the plugin, with the new message the code was
supposed to produce:

   dsh: warning: 1 entry did not activate
   grok-workflow (dsh-grok-workflow): Error: removed configuration key "mode":
     it was removed in an earlier release and is no longer accepted; delete it
     from your patch
       at assertKnownKeys (lib/config.js:719:19)
       at resolveConfig (lib/config.js:1053:5)
       at readConfig (lib/index.js:62:33)
       at new apply (lib/index.js:106:20)

This is the intended behaviour (CONFIRMED on a real profile), and it is a
migration note for the release: `mode` and `legacyGate` must be deleted from
every existing `cordis.patch.yml`. After removing that one line the plugin
activated with no warning.

Two further setup-only failures were mine, not the plugin's: re-pointing every
model route at one provider made `roles.worker` repeat the same route twice, and
the subagent model-selection list repeat it three times. Both were refused with
their own messages ("roles.worker repeats the same route twice", "subagent model
selection repeats route …"); deduplicating the scratch patch cleared them.
