# 真机矩阵的硬规范：工作区隔离

这份文件是**纪律**，不是建议。它从两次真实事故里长出来：

- **t54**：三轮团队档样本被输入 `:3100`，而该 profile 的工作区是用户真实项目目录
  `/home/fish/project_jobs`；团队档照做的结果是 `.backups/`、`upgrade/`、`dsh-backup-copy-…/`、
  `COPY_REPORT.md`、`DB_BACKUP_REPORT.md`、`NOTIFY.md`、`.npm-cache/` 全写进了用户目录（实测 328 MB）。
- **t54 的清理当时就漏了第二批**（10:41–10:44 又有 `.backups/db-backup-20261029-104117`、`DB_BACKUP_REPORT.md`、
  `NOTIFY.md` 落下，3.6 MB），于是"已清空"的结论不成立，t56 才补清并补清单。
- **t56** 改用「先把 profile 指到 `/tmp/t56-work` 再发第一条消息」，同一批团队档样本全部落在
  `/tmp/t56-work` 里（会话目录 `sessions/--tmp-t56-work--` 就是隔离的直接证据），用户目录零新增。

## 规则


1. **先指工作区，再发第一条消息。** 任何真机样本（尤其团队档/快手档）在发出前，必须确认实例的会话工作区是一个
   一次性目录（`/tmp/t55-work/…` 之类），而不是 `$HOME` 下的真实项目。确认方式：读 `项目` 面板或
   `curl -s 127.0.0.1:<port>/…` 类健康信息，把看到的路径**写进当轮证据**（`evidence/<task>/README.md` 第 0 节）。
2. **默认只读口径：只用问答类样本。** 团队档样本天然会写盘；若本轮必须测团队档，则先把工作区指到一次性目录，
   并在 README 里写明「本轮团队档样本的工作区是 /tmp/…，跑完即弃」。
3. **跑完做「工作区差分」，而不是事后搬运。** 每轮真机测试结束前：
   - 记录开始前 `find <workspace> -newermt '<start>' | sort > before.txt` 的基线（其实是空集），
   - 结束后再扫一遍并 `diff`，任何命中都要在报告里逐条解释（新增文件/被 touch 的既有文件两类分开写）。
   - 只在**确实需要清理用户目录**时才 `mv` 到隔离区，避免把「污染」当作常规流程。
4. **事后搬运必须配清单 + 校验。** 隔离目录要有 `MANIFEST.txt`，逐项写明来源、时间、体积、是否原有文件；
   并记录 `du -sb` 总量与「隔离后原目录仍存在哪些同名项」的复核结果（t54 的清单漏掉了 10:41 之后第二批写入，
   于是「已清空」的说法不成立）。
5. **禁止把「已清理」写成结论，除非复扫为空。** 结论句必须是「复扫 `<workspace>` 于 `<时间>` 命中 0 项」这种
   可复现形式，而不是「已移出」。
6. **SQLite 也算写。** WAL 模式下，读连接会创建/改写 `*-wal` 边车文件；「我只是读了数据库」在用户目录里
   仍是 mtime 变动，报告里要写明（t54 第二批样本在 24 个 `*-wal` 上留了 10:31 的时间戳）。
7. **live 实例（:3090）永久豁免。** 任何样本、任何探针都不进 live profile 的会话；只在测试 profile 上跑。

8. **隔离要留证据。** 判据不是"我记得我指了"，而是可复现的两条：会话目录名（`sessions/--tmp-t56-work--`
   这种由工作区路径编码而来的目录）+ 页面/日志里出现的工作区名，两者都写进当轮 `evidence/<task>/README.md` 第 0 节。
9. **给测试 profile 加一个一次性工作区，是最省事的做法。** DSH 的工作区清单存在
   `$DSH_HOME/storages/workspace.json`（`tables.workspaces[uuid] = { path, title, sessionIds, … }`，
   `global.workspaceIds` 是顺序表）；停实例 → 追加一条指向 `/tmp/xxx` 的条目 → 起实例 → 在 UI 里点该工作区
   再新建会话即可，不需要改代码，也不会影响其它 profile。
10. **一次一个 turn：发下一条前必须等到本轮答案落地。** 一个会话同时只能有一个 turn 在跑；按固定预算连发
    会把后续消息直接丢掉（t56 第一轮就丢了 20 多条，会话里 `user/message` 只有 14 条）。判据要挑**权威**的
    那个：会话日志里 `assistant/message` 计数增长（`zstdcat <session>/session.v4.jsonl.zstd | grep -c '"type":"assistant/message"'`），
    而不是页面上出现档位行——页面会重渲染、会只剩侧边栏。父会话目录名是 `session-<uuid>`，子代理是裸
    `<uuid>`，取父会话要用 `ls -td .../session-*/ | head -1`。
11. **团队档样本要单独排期。** 团队档的档位行随最终回答一起到达，跑完前读不到；因此团队档样本按"启动 + 产物"
    取证，并给它单独的时间预算，不要和问答类样本混在同一轮预算里。
