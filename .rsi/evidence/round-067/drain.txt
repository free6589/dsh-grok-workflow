REGRESSION CASES (red on old code, green on new)
------------------------------------------------
1. "settles the child call already running before it cancels the run" — the real
   guardian reports one open child over the real event bus and the child's
   agent-end lands inside the window. Old code: order == ['cancel','cancel'] and
   no 'agent-end' at all. New code: agent-end precedes cancel.
2. "stops at the ceiling and says what it had to leave running" — a child that
   never reports; the window stays bounded by step count (<= 10 steps at 100 ms),
   the record reads openAtEnd 1 / deadlineHit true, and the notice says how many
   were still open.
3. "keeps the status a drained run settled with instead of stamping it cancelled"
   (src/checkpoint/wiring.ts) — finish() in flight while unload() writes; the file
   must read `completed`. Old code wrote `cancelled`.
Two guards that must stay silent are pinned too: no window when nothing is open
(an ordinary disable stays instant) and no window on a shutdown signal.

WHAT THIS DOES NOT DO
---------------------
- `kill -9` / SIGTERM remain unrecoverable by design: a shutdown signal skips the
  window instead of delaying the exit.
- The window is a ceiling, not a promise: whatever is still open at 45 s is
  cancelled and named in the record and the notice, never silently kept.
- Not committed, not pushed. lib/ was rebuilt so verify:lib stays byte-identical.
  Memory docs (STATE / HANDOFF / VALIDATION) were deliberately left to the
  integrator so parallel agents do not clobber the same files.
- No live home was written: vitest.config.ts pins GROK_WORKFLOW_CHECKPOINT_DIR and
  GROK_WORKFLOW_MEMORY_DIR to a temp dir, and this session wrote only inside the
  worktree.
